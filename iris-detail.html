Maquette d'infrastructure iris.local

Active Directory redondant · DHCP · DFS · FSRM · GPO · GLPI. Une infrastructure Windows de PME entièrement redondante, administrée par GPO, avec un outil de gestion de parc et de tickets relié à l'annuaire.

Contexte

Le projet en une phrase : une infrastructure Windows de PME entièrement redondante (deux contrôleurs de domaine, deux serveurs de fichiers), administrée par GPO, avec un outil de gestion de parc et de tickets (GLPI) relié à l'annuaire Active Directory.

Chaque service critique existe en double, et la bascule a été testée : un serveur éteint ne coupe ni l'authentification, ni l'adressage IP, ni l'accès aux fichiers.

Virtualisation sous VMware Workstation

  • Réseau VMnet8 (NAT) reconfiguré : sous-réseau 192.168.10.0/24, passerelle NAT en .254, DHCP de VMware désactivé pour que ce soit l'AD qui distribue les adresses.
  • Modèle Sysprep : une VM modèle généralisée avec sysprep /generalize /oobe /shutdown, puis des clones liés pour AD1, FIC1 et FIC2. AD2, seule VM en Core, est installée directement depuis l'ISO.
  • Sysprep supprime l'identifiant unique (SID) de la machine : sans lui, les clones auraient tous le même SID, ce qui pose problème pour la jonction au domaine. Les clones liés ne stockent que les différences avec le modèle.
  • Snapshots à chaque étape validée, VM éteintes (cohérence de l'AD au retour arrière).
  • Windows 11 exige UEFI, démarrage sécurisé et TPM 2.0 : TPM virtuel ajouté sur une VM chiffrée.

Active Directory et DNS (AD1 + AD2)

Ordre suivi : nom + IP fixe → DNS → rôle AD DS → promotion → vérifications → UO → groupes → GPO. Un DC ne se renomme jamais après sa promotion.

Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "iris.local" -DomainNetbiosName "IRIS" `
  -ForestMode "WinThreshold" -DomainMode "WinThreshold" -InstallDns:$true

# Sur AD2 (DNS pointé sur AD1 AVANT la promotion)
Install-ADDSDomainController -DomainName "iris.local" `
  -Credential (Get-Credential "IRIS\Administrateur") -InstallDns:$true `
  -ReplicationSourceDC "AD1.iris.local"

  • DNS croisés : chaque DC interroge l'autre en premier, lui-même en second. Ça évite l'« îlot DNS » où un DC ne verrait plus les mises à jour de son partenaire.
  • Zone de recherche inversée 192.168.10.0/24 créée (sinon nslookup affiche « UnKnown »).
  • Redirecteurs 1.1.1.1 et 8.8.8.8 pour résoudre les noms Internet.
  • NTP : le PDC (AD1) se synchronise sur fr.pool.ntp.org ; tout le domaine se cale sur lui. Kerberos refuse un écart de plus de 5 minutes.
  • Tolérance de panne testée : avec AD1 éteint, %LOGONSERVER% affiche \\AD2 sur le poste client.

DHCP en basculement

Add-DhcpServerInDC -DnsName AD1.iris.local -IPAddress 192.168.10.10
Add-DhcpServerv4Scope -Name "LAN-IRIS" -StartRange 192.168.10.100 `
  -EndRange 192.168.10.200 -SubnetMask 255.255.255.0 -State Active
Set-DhcpServerv4OptionValue -ScopeId 192.168.10.0 -Router 192.168.10.254 `
  -DnsServer 192.168.10.10,192.168.10.11 -DnsDomain iris.local
Add-DhcpServerv4Failover -ComputerName AD1.iris.local -Name "Failover-AD1-AD2" `
  -PartnerServer AD2.iris.local -ScopeId 192.168.10.0 -LoadBalancePercent 50
Invoke-DhcpServerv4FailoverReplication -ScopeId 192.168.10.0 -Force
  • Autorisation dans l'AD : un serveur DHCP Windows non autorisé ne distribue rien (protection contre les DHCP pirates).
  • Équilibrage 50/50 : les deux serveurs se partagent les clients ; si l'un tombe, l'autre reprend toute la plage.
  • MCLT (Maximum Client Lead Time, 1 h) : un nouveau client reçoit d'abord un bail court, le temps que les partenaires se synchronisent.
  • Une modification faite après la création du basculement (réservation) doit être répliquée avec Invoke-DhcpServerv4FailoverReplication.
  • Réservation plutôt qu'IP fixe pour le poste : il garde toujours la même adresse, mais tout reste géré depuis le serveur DHCP.

  • A-G-DL-P : compte (Account) → groupe Global (métier) → groupe Domaine Local (ressource) → Permission. Un nouvel arrivant = une seule action : l'ajouter à son GG_.
  • Une UO ne donne aucun droit : elle sert à cibler les GPO et à déléguer. Ce sont les groupes qui donnent les accès.
  • Exemple : la Direction a un accès en lecture seule à la Comptabilité, car GG_Direction est membre de DL_Comptabilite_R.
  • Création par script PowerShell (Creation-AD.ps1) : UO, groupes, imbrications, 10 utilisateurs, compte de service svc-glpi et compte d'administration nominatif.
  • redircmp : les ordinateurs joints au domaine arrivent dans OU=Postes (le conteneur Computers ne peut pas recevoir de GPO).
  • Protection contre la suppression accidentelle sur les UO.

Fichiers, DFS et FSRM

Arborescence identique sur FIC1 et FIC2 : E:\Partages\Commun, E:\Partages\Services\<service>, E:\Partages\Perso\<utilisateur>. Droits posés par script (Partages-FIC.ps1 et Perso-FIC.ps1) avec icacls.

  • Partage contre NTFS : partages ouverts aux Utilisateurs authentifiés, c'est NTFS qui filtre. Quand les deux s'appliquent, le plus restrictif gagne.
  • ABE (énumération basée sur l'accès) : chacun ne voit que les dossiers auxquels il a droit.
  • DFS-N : espace de noms de domaine \\iris.local\Partages, hébergé sur FIC1 et FIC2, avec les dossiers Commun, Services et Perso, chacun avec deux cibles.
  • DFS-R : un groupe de réplication par dossier, maille pleine, FIC1 en membre principal (il fait foi à la première synchronisation).
  • FIC2 en « Dernier parmi toutes les cibles » : tout le monde travaille sur FIC1 tant qu'il répond, ce qui évite les conflits d'écriture (DFS-R ne verrouille pas les fichiers).
  • Bascule côté client : quand FIC1 ne répond plus, le poste redemande la liste des cibles et passe sur FIC2, en quelques secondes à une minute. Un fichier créé pendant la panne se retrouve sur FIC1 à son retour, grâce à DFS-R.

FSRM : quotas et filtrage

  • Modèle de quota « Service 500 Mo », inconditionnel (bloque l'écriture), avertissement à 85 % dans le journal des événements.
  • Quota automatique sur E:\Partages\Services : chaque sous-dossier reçoit ses propres 500 Mo, y compris un service créé plus tard.
  • Filtre actif « Bloquer les fichiers audio et vidéo » sur Commun.
  • Les réglages FSRM ne sont pas répliqués par DFS : configuration refaite sur FIC1 et FIC2.
  • Tests : un fichier de 600 Mo dans RH donne « Erreur 112 : espace insuffisant » ; un .mp3 dans Commun donne « Accès refusé ».

GLPI : gestion de parc et assistance

Pile LAMP sur Debian 13 : Linux, Apache 2.4, MariaDB 11.8, PHP 8.4. GLPI 11.0.13, choisi car c'est une version supportée compatible avec les paquets de Debian (GLPI 12 a des prérequis plus élevés).

  • DocumentRoot sur /public : la configuration (avec le mot de passe de la base) n'est pas accessible depuis le web.
  • Utilisateur MariaDB dédié avec des droits sur sa seule base : moindre privilège.
  • Sécurisation : données de démonstration désactivées, mots de passe des comptes par défaut changés, install.php supprimé, session.cookie_httponly activé.
  • Enregistrement DNS glpi.iris.local (A + PTR) sur AD1.

Pannes rencontrées et résolues

Pour chaque panne : le symptôme, la commande de diagnostic, la cause et la correction.

Réplication en échec, GPO illisibles (événement 1058)

Diagnostic : Get-NetConnectionProfile → réseau en Public.

Cause : le service de détection réseau démarre avant l'AD et classe le réseau en Public : le pare-feu bloque.

Correction : Restart-NetAdapter ; dépendance de NlaSvc sur DNS/NTDS ; démarrage différé (delayed-auto).

nslookup : « Serveur UnKnown, Address ::1 » et délai

Diagnostic : Get-DnsClientServerAddress.

Cause : la promotion a ajouté ::1 (localhost IPv6) en DNS.

Correction : Set-DnsClientServerAddress -ResetServerAddresses puis 127.0.0.1.

repadmin : erreurs 1722 et 58

Diagnostic : Resolve-DnsName du CNAME _msdcs d'AD2.

Cause : AD1 interrogeait d'abord le DNS d'AD2, dont la copie de zone était incomplète.

Correction : DNS d'AD1 temporairement sur 127.0.0.1 en premier, Clear-DnsClientCache, puis DNS recroisés.

repadmin : erreurs 5 (accès refusé) et 1326

Diagnostic : analyse des codes d'erreur.

Cause : tickets Kerberos périmés après le changement de mot de passe machine d'AD2.

Correction : klist purge et klist -li 0x3e7 purge.

repadmin : « topologie incomplète », erreur 1908

Diagnostic : repadmin /showrepl.

Cause : le KCC n'avait pas encore créé les liens ; échecs en cache.

Correction : repadmin /kcc sur les deux DC, redémarrage d'AD2.

Dossiers de service lisibles par tous

Diagnostic : chemin E:\Partages\Commun\Services.

Cause : Services rangé dans Commun : DL_Commun_RW hérité partout.

Correction : script de correction : icacls /reset puis droits AGDLP reposés.

Pas de lecteur E: sur les serveurs de fichiers

Diagnostic : Gestion des disques.

Cause : disque ajouté dans VMware mais pas initialisé.

Correction : initialisation GPT, volume simple NTFS « DATA ».

CLI-01 en 169.254 (APIPA)

Diagnostic : IP fixe temporaire + ping : réseau OK.

Cause : DC éteints au moment de la demande, puis service DHCP ne répondant pas.

Correction : vérification des services, des liaisons DHCP et du pare-feu, puis ipconfig /renew.

Erreur 1722 sur la réplication

Diagnostic : repadmin /replsummary : dernier succès il y a 23 h.

Cause : AD2 éteint depuis la veille.

Correction : démarrage d'AD2 et resynchronisation (un DC peut rester absent jusqu'à 180 jours).

Bascule DFS qui semble ne pas marcher

Diagnostic : onglet DFS des propriétés du dossier.

Cause : délai de bascule côté client (cache des références).

Correction : attendre, ou vider l'historique / définir la cible active.

Windows 11 refuse de s'installer

Diagnostic : écran « ne répond pas à la configuration requise ».

Cause : prérequis matériels non détectés.

Correction : clé LabConfig (BypassTPMCheck…), prévue par Microsoft pour les labos.

Debian : DHCP en échec à l'installation

Cause : DC pas encore prêts.

Correction : configuration manuelle de l'IP fixe dès l'installation.

mysql_secure_installation introuvable

Cause : MariaDB 11 a renommé ses commandes.

Correction : mariadb-secure-installation, mariadb, mariadb-tzinfo-to-sql.

glpi.iris.local : NXDOMAIN

Diagnostic : message du navigateur.

Cause : enregistrement DNS absent.

Correction : nouvel hôte A + PTR dans la zone iris.local, ipconfig /flushdns.

GLPI : test LDAP échoué

Diagnostic : ldapsearch → « Strong(er) authentication required (8) ».

Cause : Windows Server 2025 impose la signature LDAP par défaut.

Correction : signature assouplie dans la Default Domain Controllers Policy (piste d'amélioration : LDAPS).

Pistes d'évolution

Limite connue : la liaison GLPI-AD n'est pas chiffrée. Windows Server 2025 impose la signature LDAP ; pour la maquette, elle a été assouplie sur les DC, ce qui fait circuler le mot de passe de svc-glpi en clair. En attendant, ce compte n'a que des droits de lecture.

  • LDAPS (port 636) entre GLPI et l'AD, avec une autorité de certification AD CS, et rétablir la signature LDAP obligatoire.
  • GLPI en HTTPS avec un certificat de cette même AD CS, ce qui permet aussi d'activer session.cookie_secure.
  • Déploiement de l'agent GLPI par GPO sur l'UO Postes, pour que chaque nouvelle machine remonte automatiquement.
  • Sauvegardes : Windows Server Backup sur les DC (état du système), sauvegarde de la base MariaDB (mariadb-dump) et du dossier files de GLPI, Backup-GPO.
  • Mises à jour centralisées (WSUS) et supervision des serveurs.
  • Stratégies de mot de passe affinées (PSO) pour les comptes à privilèges.
  • Licences : passer les VM d'évaluation (180 jours) en licences réelles.
